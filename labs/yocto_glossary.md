# Yocto glossary

The variables and keywords used in this repository: in the layer files (`conf/`, `recipes-*/`, `kas-project.yml`) and in the labs. For each entry: what it is for, and how it is used here.

To see the final value of any variable and where it was set, use `bitbake-getvar -r <recipe> VAR` or `bitbake -e <recipe> | less`, then search for `^# \$VAR`.

---

## Assignment operators and syntax

| Syntax | Meaning | Where we use it |
|---|---|---|
| `=` | Plain assignment; the value is expanded when it is used | most variables |
| `?=` | Assign only if nothing is set yet | `PREFERRED_PROVIDER_virtual/kernel ?=` (machine); meta-ti `k3.inc` uses it for `WKS_FILE` and `IMAGE_BOOT_FILES` |
| `??=` | Weak default; any other assignment wins | seen in Poky: `EFI_PROVIDER ??= "grub-efi"` in `packagegroup-core-boot.bb` |
| `:=` | Expand the value immediately, at parse time | `FILESEXTRAPATHS:prepend := "${THISDIR}/files:"`, so that `THISDIR` is the directory of the `.bbappend` |
| `+=` / `.=` | Append with / without a space, at parse time | `IMAGE_FSTYPES +=`, `BBFILES +=`, `BBPATH .=` |
| `:append` / `:prepend` | Append / prepend at the end of parsing, after all `=`, `?=`, `+=`; needs a leading space for lists | `MACHINE_FEATURES:append`, `IMAGE_BOOT_FILES:append`, `SRC_URI:append`, `CFLAGS:append` |
| `:remove` | Remove words from a list, applied last | `MACHINE_FEATURES:remove = "efi"` |
| `VAR:<override>` | Value used only when the override is active (machine, distro, arch, `pn-<recipe>`) | `PREFERRED_PROVIDER_virtual/kernel:beagley-ai` (Lab 2); `files/beagley-custom/` lookup (see `FILESOVERRIDES`) |
| `VAR[flag]` | A flag of a variable or task | `SRC_URI[sha256sum]`, `do_image_wic[depends]` |
| `${VAR}` | Expand another variable | everywhere |
| `require` / `include` | Include another `.conf`/`.inc`/`.bb`; `require` fails if the file is missing | `require conf/machine/beagley-ai.conf`, `require conf/distro/poky.conf`, `require recipes-core/images/core-image-minimal.bb` |
| `inherit` | Use a class (`.bbclass`) | `inherit deploy` in `extlinux-conf` |

## Layer configuration (`conf/layer.conf`, `bblayers.conf`)

| Variable | What it is for | How we use it |
|---|---|---|
| `LAYERDIR` | Path of the layer being parsed (valid only in `layer.conf`) | base for `BBPATH`, `BBFILES`, `BBFILE_PATTERN` |
| `BBPATH` | Search path for `conf/` and `classes/` files | `BBPATH .= ":${LAYERDIR}"` lets BitBake find our `conf/machine/*.conf` and `conf/distro/*.conf` |
| `BBFILES` | Glob patterns of recipes and appends | `recipes-*/*/*.bb` and `*.bbappend`: recipes must be exactly two levels below the layer root |
| `BBFILE_COLLECTIONS` | Internal name of the layer | `meta-beagley-ai` |
| `BBFILE_PATTERN_<layer>` | Regex that tells which recipe files belong to the layer | `^${LAYERDIR}/` |
| `BBFILE_PRIORITY_<layer>` | Priority when several layers provide the same recipe | `6` |
| `LAYERDEPENDS_<layer>` | Layers that must be present | `core meta-ti-bsp meta-beagle` |
| `LAYERSERIES_COMPAT_<layer>` | Compatible Yocto releases | `scarthgap` |
| `LAYERVERSION_<layer>` | Version of the layer (optional) | generated by `bitbake-layers create-layer` (Lab 4) |
| `BBLAYERS` | List of enabled layers, in `build/conf/bblayers.conf` | edited by hand in Lab 1, generated by kas since Lab 9 |

## Build configuration (`local.conf`, kas)

| Variable | What it is for | How we use it |
|---|---|---|
| `MACHINE` | Target board; selects `conf/machine/${MACHINE}.conf` | `beagley-ai` (Labs 1–5), `beagley-custom` since Lab 6 (`machine:` in kas) |
| `DISTRO` | Distribution; selects `conf/distro/${DISTRO}.conf` | `poky` (Labs 1–8), `beagley-distro` since Lab 9 (`distro:` in kas) |
| `TOPDIR` | The build directory | `${TOPDIR}/../meta` paths in `bblayers.conf` (Lab 1) |
| `INHERIT` | Classes applied globally | `rm_work` (Lab 1, saves disk), `buildhistory` (planned) |
| `EXTRA_IMAGE_FEATURES` | Image features added from `local.conf` for every image | `debug-tweaks` in Lab 1 |
| `PACKAGE_CLASSES` | Package format(s): `package_rpm`, `package_ipk`, `package_deb` | Poky default `package_rpm`; that is why the packages are `.rpm` |
| `PREFERRED_PROVIDER_<virtual>` | Which recipe provides a virtual target | see the "Machine" section |

## Machine (`conf/machine/beagley-custom.conf` and meta-ti)

| Variable | What it is for | How we use it |
|---|---|---|
| `MACHINE_FEATURES` | Hardware features of the board; recipes and packagegroups react to them | `:append = " usbhost vfat serial"`; `:remove = "efi"` drops GRUB and switches the WKS (Lab 10) |
| `PREFERRED_PROVIDER_virtual/kernel` | Recipe that provides the kernel | `linux-bb.org` (BeagleBoard.org kernel 6.12) |
| `IMAGE_FSTYPES` | Output image formats | `+= "tar.xz wic"`: `tar.xz` for NFS, `wic` for the SD card (meta-ti adds `wic.xz wic.bmap`) |
| `IMAGE_BOOT_FILES` | Files copied from `DEPLOY_DIR_IMAGE` to the FAT boot partition; `src;dst` renames | `:append` adds `Image`, the DTB to `dtb/ti/` and `extlinux.conf` to `extlinux/` (Lab 10) |
| `WKS_FILE` | wic kickstart file that describes the SD card partitions | not set by us; `k3.inc` picks `sdimage-2part.wks` because `efi` is removed |
| `EFI_PROVIDER` | EFI bootloader used when `efi` is in `MACHINE_FEATURES` | `grub-efi` from `k3.inc`; no longer used since Lab 10 |
| `KERNEL_DEVICETREE` | DTBs and DTBOs built with the kernel | from `beagley-ai.conf`: `k3-am67a-beagley-ai.dtb` and its overlays |
| `MACHINE_ESSENTIAL_EXTRA_RDEPENDS` | Packages every image of the machine must contain | `kernel-image-image` (`k3.inc`) and `kernel-devicetree` (`ti-soc.inc`): the second copy of kernel and DTBs in `/boot` |
| `MACHINE_ARCH` | Package architecture specific to this machine (`beagley_custom`) | `PACKAGE_ARCH` of `extlinux-conf` |
| `TI_COMMON_DEPLOY` | meta-ti common deploy directory for the A53 and R5 builds | why everything lands in `build/deploy-ti/` |
| `${MACHINE}-k3r5` | Not a variable: the name the meta-ti `k3r5` multiconfig looks up | requires `conf/machine/beagley-custom-k3r5.conf` (Lab 6) |

## Recipe metadata

| Variable | What it is for | How we use it |
|---|---|---|
| `PN` / `PV` | Package name and version, taken from the file name `<PN>_<PV>.bb` | `ninvaders` / `0.1.1`; `${PV}` in the nInvaders `SRC_URI` |
| `SUMMARY` / `DESCRIPTION` | Short and long description | all our recipes and the kernel bbappend |
| `HOMEPAGE` | Project URL | nInvaders |
| `SECTION` | Software category | `console/games` |
| `LICENSE` | SPDX license identifier | `GPL-2.0-only` (nInvaders), `MIT` (image, `extlinux-conf`) |
| `LIC_FILES_CHKSUM` | File with the license text and its MD5; detects license changes | `nInvaders.c;md5=...`; `${COMMON_LICENSE_DIR}/MIT` for our own files |
| `COMMON_LICENSE_DIR` | Directory with the standard license texts in Poky | MIT license checksum in `extlinux-conf` |

## Sources and file lookup

| Variable | What it is for | How we use it |
|---|---|---|
| `SRC_URI` | What to fetch: archives, git, local `file://` | nInvaders tarball; `file://extlinux.conf`; `file://enable-extra-options.cfg` and `file://disable-unused.cfg` via `:append` |
| `SRC_URI[sha256sum]` | Checksum of a downloaded archive | nInvaders tarball |
| `SOURCEFORGE_MIRROR` | Base URL of the SourceForge downloads | nInvaders `SRC_URI` |
| `THISDIR` | Directory of the file being parsed | `${THISDIR}/files` in the bbappends |
| `FILESEXTRAPATHS` | Extra directories to search for `file://` entries | `:prepend := "${THISDIR}/files:"` in the kernel and `base-files` bbappends |
| `FILESPATH` | Final search list for `file://`, built from `FILESEXTRAPATHS` and `FILESOVERRIDES` | explains why our files win over the originals (Lab 5) |
| `FILESOVERRIDES` | Override names tried as subdirectories (`files/<override>/`) | `files/beagley-distro/motd` (distro), `files/beagley-custom/fstab` (machine) |

## Work directories

| Variable | What it is for | How we use it |
|---|---|---|
| `WORKDIR` | Work directory of a recipe in `tmp/work/` | where `file://` sources are unpacked; source of `extlinux.conf` in `do_deploy`; kernel fragments as `${WORKDIR}/*.cfg` in `KERNEL_CONFIG_FRAGMENTS` |
| `S` | Unpacked source directory | `${WORKDIR}` for `extlinux-conf`; `ninvaders-0.1.1/` for nInvaders |
| `B` | Build directory (objects) | kernel `.config` in `build/` (Lab 5) |
| `D` | Install destination, packaged afterwards (`image/` in `WORKDIR`) | `${D}${bindir}` in nInvaders `do_install` |
| `bindir` | `/usr/bin` | install path of `ninvaders` |
| `DEPLOYDIR` | Output directory of `do_deploy`, copied to `DEPLOY_DIR_IMAGE` | `extlinux-conf` deploys `extlinux.conf` there |
| `DEPLOY_DIR_IMAGE` | Where images, bootloaders, kernel and DTBs are deployed | `build/deploy-ti/images/beagley-custom/`; wic builds the FAT partition from it |

## Compiling and packaging

| Variable | What it is for | How we use it |
|---|---|---|
| `DEPENDS` | Build-time dependencies (headers and libraries in `recipe-sysroot`) | `ncurses` for nInvaders |
| `CC` | Cross compiler with sysroot and machine flags | passed to the nInvaders Makefile; `$CC` from the SDK (Lab 8) |
| `CFLAGS` / `LDFLAGS` | Compiler and linker flags | `CFLAGS:append = " -std=gnu17 -fcommon"` fixes old C code |
| `EXTRA_OEMAKE` | Extra arguments for `make` in `oe_runmake` | overrides the hard-coded `CC=gcc` and `CFLAGS` of the nInvaders Makefile |
| `PACKAGE_ARCH` | Architecture of the produced package | `${MACHINE_ARCH}` for `extlinux-conf` (board-specific file) |

## Tasks, classes and task flags

| Name | What it is for | How we use it |
|---|---|---|
| `do_compile` / `do_install` | Build, then install into `${D}` (→ package → rootfs) | nInvaders `do_install` |
| `do_deploy` (`inherit deploy`) | Put files into `DEPLOY_DIR_IMAGE`, outside the rootfs | `extlinux-conf`: file goes to the FAT partition, not to the rootfs |
| `addtask` | Add a task to the task graph | `addtask deploy after do_compile before do_build` |
| `do_image_wic[depends]` | Extra dependency of the wic image task | `+= "extlinux-conf:do_deploy"` because `extlinux-conf` is not an image package |
| `do_configure` (kernel) | Creates the kernel `.config` | for `linux-bb.org` the meta-ti version in `setup-defconfig.inc`: defconfig + `merge_config.sh -m`; `bitbake -c configure [-f] virtual/kernel` checks fragments in seconds (Lab 11) |
| `do_menuconfig` / `do_diffconfig` | Interactive Kconfig menu / write the changes since `menuconfig` to `${WORKDIR}/fragment.cfg` (`cml1.bbclass`) | needs a tmux shell in the container; source of exact option names for a fragment (Lab 11) |

## Kernel

| Name | What it is for | How we use it |
|---|---|---|
| `KERNEL_CONFIG_FRAGMENTS` | meta-ti list of `.cfg` fragments merged into `.config` by `merge_config.sh` (`setup-defconfig.inc`); `SRC_URI` alone only fetches them | `${WORKDIR}/enable-extra-options.cfg` and `${WORKDIR}/disable-unused.cfg` (Lab 11) |
| `KERNEL_LOCALVERSION` | Suffix passed to the kernel build, added after `CONFIG_LOCALVERSION` | `-ti` from `setup-defconfig.inc`; gives `6.12.57-beagley-ti` |
| `CONFIG_I2C_CHARDEV` | `/dev/i2c-*` for user space | in `enable-extra-options.cfg`; also enabled by `bb.org_defconfig` |
| `CONFIG_DYNAMIC_DEBUG` | Runtime-switchable kernel debug messages | in `enable-extra-options.cfg`; also enabled by `bb.org_defconfig` |
| `CONFIG_LOCALVERSION` | String appended to the kernel release (`uname -r`, `/lib/modules/<release>`) | `-beagley` in `enable-extra-options.cfg`: proves the fragment is applied (Lab 11) |
| `CONFIG_IKCONFIG_PROC` | Kernel configuration readable at `/proc/config.gz` | from `bb.org_defconfig`; checks the configuration on the board |
| `CONFIG_MEDIA_SUPPORT_FILTER` | Makes the `MEDIA_*_SUPPORT` options selectable; without it they are forced on | `=y` in `disable-unused.cfg` to drop TV, radio and SDR (Lab 11) |
| `# CONFIG_X is not set` | Fragment syntax that disables an option | 100 lines in `disable-unused.cfg`; a line for an option without a prompt is dropped silently (Lab 11) |
| `CONFIG_ROOT_NFS`, `CONFIG_IP_PNP` | Root filesystem over NFS, kernel IP configuration | built in; needed for NFS root (Lab 2) |
| `CONFIG_VFAT_FS` | FAT filesystem | built in; mounts `/boot/firmware` (Lab 10) |

## U-Boot environment and extlinux (Lab 10)

| Name | What it is for | How we use it |
|---|---|---|
| `boot_targets` | Boot devices scanned by `bootflow scan` | `mmc1` (SD card) |
| `bootmeths` | Boot methods tried on each partition, in order | `script extlinux efi pxe` |
| `fdtfile` | Default DTB name | `ti/k3-am67a-beagley-ai.dtb` |
| `kernel_addr_r` / `fdt_addr_r` / `fdtoverlay_addr_r` | RAM load addresses for kernel, DTB and overlays | used by extlinux; and by `load` + `booti` for a manual boot |
| `MENU TITLE` | Enables the interactive boot menu | `BeagleY-AI boot menu` |
| `TIMEOUT` / `DEFAULT` | Menu timeout (tenths of a second) / default label | `30` / `beagley` |
| `LABEL` / `MENU LABEL` | Boot entry and its menu text | `beagley`, `safe` |
| `KERNEL` / `FDT` / `APPEND` | Kernel, DTB and kernel command line | `../Image`, `../dtb/ti/k3-am67a-beagley-ai.dtb`, `root=/dev/mmcblk1p2 ...` |
| `FDTOVERLAYS` | Space-separated `.dtbo` list applied to the DTB | commented out by default; enabled on the board |
